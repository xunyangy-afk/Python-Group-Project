## Refinements made after the first validation run

1. **Placeholder news.** The first rule flagged 20 rows. Reading them showed 12 were long, real summaries that only said one of several articles was empty. The rule now requires the placeholder phrasing in a short text (< 1,000 characters) or a fragment (< 200 characters). Result: 8 rows, all confirmed by reading.
2. **Look-ahead news.** A keyword search matched 33 rows, but nearly all were disclaimers stating that future information had been excluded, the opposite of a leak. The rule now compares explicit dates written in the text with the row date. Result: 1 row (ADBE 2025-02-15 mentions the 2025-02-25 Photoshop for iPhone launch), a real leak.
3. **Encoded characters in filings.** Building the checklist evidence showed that filings text stores characters as HTML entities (`&#8217;` for a right quote, `&#160;` for a non-breaking space, `&#38;` for &). All 73 MD&A sections and 68 risk sections were affected; news had none. These are decoded to the real characters, which changes encoding, not wording, and makes text lengths and keyword searches reliable.

## Conclusion: does the cleaned data still represent reality?

Yes. No rows were dropped and no original values or wording were changed beyond whitespace, so every price, news summary, and filing is still what the benchmark agents actually received. Prices pass all logic checks, and the 9 large moves line up with known events (2025-04-09 tariff pause rally, NVDA DeepSeek drop on 2025-01-27). The quality problems are now visible through flags instead of hidden: 8 empty news rows, 1 look-ahead leak, 1,232 non-trading-day news rows aligned to the next session, and 12 filings whose risk section is repeated or only refers to the 10-K. Anyone analysing agent report quality should filter or control for these flags rather than treat all rows as equal.
